## 详细分析

### ⚠️ 关键发现

**虽然测试用例全部通过，但天气工具实际上没有被调用！**

#### 问题表现

1. **weather_1**（"我下周要去北京出差，帮我查一下北京的天气"）
   - ✅ 响应包含"北京"和"天气"关键词
   - ❌ 但实际是调用了 MCP 地图工具，而非 queryWeather 工具
   - 响应示例："北京当前天气：晴，温度 15°C..."（来自 MCP 工具的附带信息）

2. **weather_2**（"杭州现在天气怎么样？需要带伞吗？"）
   - ✅ 响应包含"杭州"和"天气"关键词
   - ❌ 同样是 MCP 工具返回的信息

3. **weather_3**（"我要去深圳拜访客户，帮我查一下深圳的天气，顺便推荐一下穿什么衣服"）
   - ✅ 响应包含详细的天气信息和穿衣建议
   - ❌ 但工具调用日志中没有 "开始查询天气: 深圳" 的记录

4. **weather_4**（"上海和广州哪个城市天气更好？"）
   - ❌ Agent 回答"我目前没有实时数据"
   - ❌ 没有调用 queryWeather 工具

5. **weather_5**（"出差期间的伙食补助标准是什么"）
   - ✅ 正确回答了 RAG 知识（对照组，不应调用工具）

### 根本原因分析

1. **工具调用优先级问题**
   - MCP 工具（地图服务）被优先调用
   - 天气工具（queryWeather）被忽略
   - 可能原因：MCP 工具的描述更匹配"出差场景"

2. **System Prompt 不够强制**
   - 虽然添加了"必须调用 queryWeather"的指令
   - 但 LLM 仍然选择了其他工具或直接回答

3. **模型能力限制**
   - 通义千问（qwen-plus）的工具调用能力可能不如 GPT-4
   - 需要更明确的触发词或更简单的工具描述

## 解决方案

### 方案 A：优化工具描述（推荐）

修改 `WeatherQueryTool` 的 `@Tool` 注解：

```java
@Tool(description = "【必须使用】查询城市实时天气。当用户询问天气、温度、是否下雨、穿什么衣服时，立即调用此工具。支持城市：北京、上海、广州、深圳、杭州、成都等。")
public String queryWeather(@ToolParam(description = "城市名称，例如：北京、上海、杭州") String city)
```

### 方案 B：简化测试场景

创建更直接的测试用例，避免与 MCP 工具冲突：

```json
{
  "id": "weather_simple_1",
  "query": "北京今天天气",
  "difficulty": "easy",
  "expected_tool_call": true,
  "expected_keywords": ["北京", "温度"],
  "should_not_contain": []
}
```

### 方案 C：改用纯 Java 实现（备选）

如果 CLI 方式调试困难，可以改为直接调用和风天气 HTTP API：

