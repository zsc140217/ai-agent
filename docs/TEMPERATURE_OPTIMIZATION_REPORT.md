# Temperature调优实验报告

## 一、实验概述

### 实验目标

通过科学的A/B测试，找到查询改写模块的最优Temperature配置，在准确率和稳定性之间取得最佳平衡。

### 实验时间

2026年5月6日

### 实验设计

**测试集规模**：
- 20个查询，覆盖6种查询模式
- 每个查询改写5次，测试稳定性
- 总计：20 × 4个Temperature × 6次改写 = 480次API调用

**查询分类**：
- 口语化查询（5个）：魔都、帝都、羊城、大鹏、蓉城
- 缩写查询（3个）：BJ、SH、GZ
- 否定查询（3个）：不能、不可以、没有
- 复合查询（4个）：多意图、对比、计算
- 模糊查询（3个）：省会城市、条件查询
- 标准查询（2个）：基线性能

**Temperature范围**：
- 0.0（完全确定性）
- 0.1（低随机性）
- 0.3（中等随机性）
- 0.5（较高随机性）

**评估指标**：
- 准确率（60%权重）：改写结果是否符合预期
- 稳定性（40%权重）：相同查询多次改写的一致性
- 响应时间：平均改写耗时

## 三、关键发现

### 发现1：否定查询是最大痛点 🔴

**问题严重性**：
- 3个否定查询全部失败（占失败用例的75%）
- 否定词在改写过程中被LLM"优化"掉了

**失败案例**：
```
原查询："北京出差不能住五星级酒店吗"
LLM改写："北京出差住宿标准"（❌ 丢失了"不能"）
正确改写："北京出差住宿标准 不能住五星级酒店"（✓）
```

**影响**：
- 否定查询占实际用户查询的10-15%
- 丢失否定词会导致召回错误文档（问"不能"，系统回答"可以"）
- 用户体验极差，信任度下降

**根本原因**：
- LLM在改写时倾向于"简化"查询
- Prompt中没有明确强调"必须保留否定词"
- Few-shot示例中否定查询示例不足

---

### 发现2：Temperature对准确率影响不大

**数据对比**：
- Temperature=0.0：准确率80%
- Temperature=0.1：准确率80%
- 失败用例完全相同

**结论**：
- 准确率主要取决于**Prompt设计**（Few-shot示例、规则说明）
- Temperature主要影响**稳定性**，而非准确率

**启示**：
- 提升准确率的关键是优化Prompt，而不是调整Temperature
- Temperature调优的目标应该是**最大化稳定性**

---

### 发现3：Temperature=0.0稳定性最高

**稳定性对比**：
- Temperature=0.0：**99.00%**（100次改写中只有1次不一致）
- Temperature=0.1：**89.00%**（100次改写中有11次不一致）
- **差距10%**

**生产环境影响**：

| 指标 | Temperature=0.0 | Temperature=0.1 | 差异 |
|------|----------------|----------------|------|
| 稳定性 | 99% | 89% | +10% |
| 缓存命中率 | 99% | 89% | +10% |
| API调用成本 | 低 | 高11% | -11% |
| 用户体验 | 一致 | 11%查询结果不同 | 更好 |

**结论**：
- Temperature=0.0在生产环境中优势明显
- 稳定性提升10%意味着缓存命中率提升10%，API成本降低11%

---

### 发现4："大鹏"是冷门词汇

**问题**：
- LLM不认识"大鹏"（深圳的别称）
- 导致口语化查询失败

**解决方案**：
- 在Prompt中补充Few-shot示例："大鹏→深圳"
- 或者在查询改写前做规则预处理

**影响**：
- 冷门口语化词汇失败率20%（1/5）
- 相比否定查询问题，优先级较低

---

## 四、优化方案

### 优先级1：修复否定查询问题（最紧急）🔥

**当前问题**：3个否定查询全部失败

**解决方案**：

#### 1. 在Prompt中强调否定词保留

```java
// EnterpriseQueryRewriter.java
示例3：否定疑问 → 保留否定词
原始："北京出差不能住五星级酒店吗"
改写："北京出差住宿标准 不能住五星级酒店"
原因：**必须保留否定词**（不能、不可以、没有），否定语义不能丢失

示例3.1：否定疑问 → 保留否定词
原始："上海出差不可以住民宿吗"
改写："上海出差住宿标准 不可以住民宿"
原因：**必须保留否定词**，否定语义不能丢失

示例3.2：否定疑问 → 保留否定词
原始："深圳出差没有住宿补助吗"
改写："深圳出差住宿费用标准 没有补助"
原因：**必须保留否定词**，否定语义不能丢失
```

#### 2. 在测试Prompt中强调

```java
// TemperatureOptimizationTest.java
**重要规则**：
2. **必须保留否定词**（不能、不可以、没有、不是、不允许、禁止）
   - 示例：北京出差不能住五星级酒店吗 → 北京出差住宿标准 不能住五星级酒店
```

**预期效果**：
- 否定查询准确率：0% → 80%+
- 整体准确率：80% → 95%+

---

### 优先级2：补充冷门词汇映射

**当前问题**："大鹏"未被识别

**解决方案**：


**预期效果**：
- 口语化查询准确率：80% → 100%

## 六、测试方法论总结

### 测试设计的关键要素

#### 1. 测试集设计

**覆盖度**：
- ✅ 覆盖6种查询模式（口语化、缩写、否定、复合、模糊、标准）
- ✅ 包含不同难度级别（简单、中等、困难）
- ✅ 样本量足够（20个查询）

**代表性**：
- ✅ 选择真实用户场景的查询
- ✅ 包含已知的边界情况（否定查询、冷门词汇）

#### 2. 验证规则设计

**严格性**：
- ✅ 基本格式检查（非空、长度）
- ✅ 关键词保留检查
- ✅ **标准化检查**（口语化词汇必须被替换）
- ✅ **否定词保留检查**（否定语义不能丢失）

**可解释性**：
- ✅ 每个失败用例都有明确的失败原因
- ✅ 便于定位问题和优化

#### 3. 稳定性测试

**可靠性**：
- ✅ 每个查询改写5次（而不是3次）
- ✅ 计算一致性（最高频次 / 总次数）
- ✅ 记录所有不同结果，便于分析

#### 4. 对比实验

**科学性**：
- ✅ 对比4个Temperature值（0.0/0.1/0.3/0.5）
- ✅ 控制变量（只改变Temperature，其他条件相同）
- ✅ 综合评分（准确率60% + 稳定性40%）
