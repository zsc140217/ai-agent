## 技术架构分析

### 工作流编排器设计

```java
public String route(String query, String chatId) {
    // 1. 简单天气查询 → 预编排
    if (isSimpleWeatherQuery(query)) {
        return handleSimpleWeather(query, chatId);
    }
    
    // 2. 多城市对比 → 预编排
    if (isWeatherComparison(query)) {
        return handleWeatherComparison(query, chatId);
    }
    
    // 3. 复杂场景 → LLM 决策
    return enterpriseAssistantApp.doComprehensiveChat(query, chatId);
}
```

### 路由规则

| 场景 | 示例 | 策略 | 原因 |
|------|------|------|------|
| 简单天气查询 | "北京天气" | 预编排 | 确定性需求，直接调用工具 |
| 多城市对比 | "上海和广州哪个天气更好" | 预编排 | 需要调用 2 次工具，顺序固定 |
| 复杂出差规划 | "帮我规划去深圳的出差" | LLM 决策 | 需要多种工具协同，顺序不固定 |
| 知识库查询 | "伙食补助标准" | LLM 决策 | 纯 RAG 查询，不需要工具 |

### 关键实现细节

#### 1. 简单天气查询（预编排）

```java
private String handleSimpleWeather(String query, String chatId) {
    // 1. 提取城市名
    String city = extractCity(query);
    
    // 2. 直接调用天气工具（不依赖 LLM）
    String weatherInfo = weatherQueryTool.queryWeather(city);
    
    // 3. 让 LLM 润色回复（只需要文本生成，不需要工具调用）
    String prompt = String.format("""
        用户询问：%s
        天气信息：%s
        请根据以上天气信息，用专业且友好的语气回答用户。
        """, query, weatherInfo);
    
    return chatClient.prompt().user(prompt).call().content();
}
```

**优势**：
- ✅ 工具调用由代码控制，100% 可靠
- ✅ LLM 只负责文本润色，不需要决策
- ✅ 即使模型能力弱，也能正常工作

#### 2. 多城市对比（预编排）

```java
private String handleWeatherComparison(String query, String chatId) {
    // 1. 提取两个城市名
    String[] cities = extractCities(query);
    
    // 2. 分别查询天气（顺序固定）
    String weather1 = weatherQueryTool.queryWeather(cities[0]);
    String weather2 = weatherQueryTool.queryWeather(cities[1]);
    
    // 3. 让 LLM 对比分析
    String prompt = String.format("""
        %s的天气：%s
        %s的天气：%s
        请对比两个城市的天气，给出建议。
        """, cities[0], weather1, cities[1], weather2);
    
    return chatClient.prompt().user(prompt).call().content();
}
```

**优势**：
- ✅ 确保两个城市都被查询（LLM 可能只查一个）
- ✅ 查询顺序可控
- ✅ 避免 LLM 回答"我没有实时数据"

## 关键发现

### 1. LLM 工具调用的局限性

**不同模型的表现**：
- GPT-4：工具调用能力强，理解力好
- 通义千问：对中文场景理解好，但工具调用较保守
- 文心一言：工具调用能力更弱

**影响因素**：
- System Prompt 的清晰度
- 工具描述的明确性
- 工具数量（工具越多，选择越困难）
- 场景复杂度（简单场景更容易触发）

### 2. 预编排工作流的优势

**稳定性**：
- 工具调用由代码控制，100% 可靠
- 不受模型能力限制
- 适合生产环境

**可控性**：
- 工具调用顺序可控
- 参数提取逻辑可控
- 错误处理可控

**性能**：
- 减少 LLM 决策开销
- 避免多轮对话（"我需要查询吗？" → "是的" → 调用工具）

### 3. 混合架构的必要性

**不是所有问题都要让 LLM 决策**：
- 简单场景：预编排更高效
- 复杂场景：LLM 决策更灵活

**工程化的关键**：
- 在智能性和稳定性之间找到平衡
- 根据场景选择合适的策略
